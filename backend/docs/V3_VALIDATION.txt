기존 라벨·학습 코드·모델·데이터를 수정하지 않습니다. 새 검증 보고서만 생성합니다.

PowerShell에서:
cd C:\Users\tel93\F1.second-screen\backend

1. 단위·경계조건 테스트
.\venv\Scripts\python.exe .\tests\test_label_v3.py

마지막 결과가 OK이고 summary.json의 status가 passed인지 확인합니다.
단위 테스트 결과: data\validation\unit_v3_<실행시각>\summary.json
테스트 개수는 최상위 테스트 메서드 수이며, 일부 메서드는 여러 subTest 입력을 확인합니다.
실패하면 전체 검증으로 넘어가지 말고 summary.json의 failures/errors를 전달합니다.

2. 67경기 원시자료 검증
.\venv\Scripts\python.exe -m app.pipeline.validate_v3_dataset

기본 대상: data\rebuild_20261125_v3
보고서: data\validation\raw_v3\summary.json 및 results.csv
정상 완료: SUMMARY status=passed passed=67/67 failed=[]
경기별 상세: session_<번호>.json, 오류가 있으면 session_<번호>_error.txt
검증기 위반 메시지의 행 번호는 해당 경기 labeled_3lap_v2.parquet의 0부터 시작하는 행 번호입니다.

경기별 전체 관측을 검사하므로 오래 걸릴 수 있으며, START 이후 한동안 출력이 없을 수 있습니다.
중단: Ctrl+C (현재 경기만 다시 계산하게 될 수 있습니다.)
재개:
.\venv\Scripts\python.exe -m app.pipeline.validate_v3_dataset --resume

원본·라벨·소스·검증 스크립트의 해시가 같은 통과 경기만 건너뜁니다.
이전 실패 경기는 다시 검사합니다. 원본이 달라졌으면 통과 결과를 재사용하지 않습니다.

특정 경기만 먼저 확인하려면 별도 보고서 폴더를 지정하세요:
.\venv\Scripts\python.exe -m app.pipeline.validate_v3_dataset --sessions 10014 9582 11731 --report-dir data\validation\raw_v3_sample
이 경우 subset_passed는 선택 경기만 통과했다는 뜻이며 전체 통과가 아닙니다.

공유할 결과:
- 단위 테스트: 마지막 OK/FAILED와 REPORT 경로. 실패하면 summary.json의 failures/errors.
- 전체 검증: 마지막 SUMMARY 한 줄. 실패하면 해당 session_<번호>_error.txt.
전체 원본 로그·대용량 Parquet를 채팅에 붙여 넣을 필요는 없습니다.

검증 범위와 한계:
